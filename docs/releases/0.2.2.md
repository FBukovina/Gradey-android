# Gradey Android 0.2.2 — direct-update preview

This update brings the Android app closer to the Gradey iOS feature set with a more adaptable interface, Personal Planner, school insights and stronger account/session handling.

- Improved phone and tablet layouts, large-text support, Czech dates, contrast and navigation spacing.
- Personal Planner with lesson links, reminders and optional owned Calendar events; timetable selection is retained when returning from a linked item.
- Grade simulation, subject insights, absence planning/corrections and a richer Today view.
- Real local Bakaláři/EduPage connections without Gradey ID, plus the existing public Google/Supabase configuration for Gradey ID account acceptance.
- Help access before sign-in, clearer unavailable-service states and updated Play Billing dependencies.
- Expanded widget and Wear implementation; the phone updater does not install the Wear companion.

## Availability and compatibility

This is a direct-download debug preview, not a completed production release or a Play Store submission. Version 0.2.2 uses internal code 5 and the same signing identity as the public 0.2.1 preview (code 3) and local parity previews (code 4). Android retains existing app data during a compatible update.

Open **App updates → Check for updates**, download the update, and confirm installation in Android. The updater reads GitHub's latest non-prerelease release; that distribution label does not establish production readiness.

If the old installation was using demo data, it stays in demo mode after updating. Choose **Leave demo** before connecting a real Gradey ID or school account.

## Known limitations

Live Gradey AI, Apple browser sign-in, Android mark-push delivery and Play/RevenueCat purchases still require service configuration and acceptance. Native support uses browser Help until configured. Real Google/school account, physical-device and paired-Wear acceptance remain pending. **Use demo data** uses sample repositories; **Continue without Gradey ID** uses real school providers stored locally on the device.

No production backend is deployed by this APK release. See [the parity audit](../ios-parity.md) and [configuration requirements](../android-configuration.md) for the remaining gates.

## Verification

The parity implementation passed 360 unit tests, 53 phone instrumentation cases and 11 Wear cases. Five targeted phone checks passed after the billing SDK update. AI and native-support device fixtures passed two each using fake services. Final version-code packaging repeats app unit tests, assembly, lint, signing and update-manifest integrity checks. These checks do not establish live-service acceptance.
