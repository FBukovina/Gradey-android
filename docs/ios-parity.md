# Android parity and release audit

Reference: [Gradey iOS commit `7487a39`](https://github.com/FBukovina/Gradely/tree/7487a39d4a3c426245c9ccd87690b2ad749f75d4), 29 September 2026. The audit uses that source snapshot, including its Planner, Intelligence 2.2, Watch, widgets and Siri work. The older local September 1 checkout is not the target.

This describes the Android 0.2.2 source, not a production acceptance result. **Implemented** means a user-facing implementation exists; it does not imply a successful real school login, AI generation, purchase or push delivery. A build with missing service configuration must not be presented as a fully working release. The direct-update preview uses version code 5; earlier local parity previews used code 4.

### Assistant and system-search platform findings — checked 29 September 2026

Google still documents App Actions through `shortcuts.xml` and a Play review/deployment process; `actions.xml` is the explicitly deprecated format. This is not evidence that every legacy built-in intent works through Gemini on current devices. The documented search intent `GET_THING` supports `en-US` and `pt-BR`; custom App Actions support only `en-US`. Neither supplies the required Czech query/creation experience. Sources: [App Actions setup](https://developer.android.com/develop/devices/assistant/get-started), [GET_THING locale support](https://developer.android.com/reference/app-actions/built-in-intents/common/get-thing), [custom-intent limits](https://developer.android.com/develop/devices/assistant/custom-intents).

The current AppFunctions overview, updated 22 September, describes an experimental Android 16+ API, Gemini private preview and an EAP for selected apps and agents; registering interest does not grant access to the complete integration. The release table lists `1.0.0-alpha12` on 23 September, with no stable release. Local development/testing is possible, but production Gemini access is an external platform gate. Google also warns that agents may process queries on a server, so on-device function execution must not be described as wholly local AI processing. Sources: [AppFunctions availability and EAP](https://developer.android.com/ai/appfunctions), [release status](https://developer.android.com/jetpack/androidx/releases/appfunctions), [integration/privacy guidance](https://developer.android.com/ai/appfunctions/add-appfunctions).

The smallest independent Android extension would search already loaded, owner/school-scoped subjects, grades, lessons and incomplete Planner items, show freshness, and open results only after revalidating current access. Optional explicit on-device dictation can fill a query or Planner draft for review and Save; it does not provide hands-free system-assistant answers. Android offers an on-device recognizer from API 31 when available. The generic recognizer may use a server, and `EXTRA_PREFER_OFFLINE` can be ignored, so a local-only implementation must not silently fall back to it. Sources: [SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer), [recognizer intent behavior](https://developer.android.com/reference/android/speech/RecognizerIntent).

AppSearch offers private app-local search and an Android 12+ platform index that may appear on system surfaces, depending on the host. Optional discovery would need explicit opt-in, minimal scoped records, expiry and serialized purge on opt-out/sign-out/account changes. Schema types default to system-visible unless explicitly disabled, and visibility configuration must be reapplied when setting the schema; cross-app sharing is separately disabled by default. A private in-app search over existing cache models avoids introducing another stored copy initially. Sources: [AppSearch storage choices](https://developer.android.com/develop/ui/views/search/appsearch), [schema visibility defaults](https://developer.android.com/reference/androidx/appsearch/app/SetSchemaRequest.Builder). No AppFunctions integration, system indexing or dictation implementation was added during this research.

## Outstanding user-facing parity work

- Validate paired Wear AI, independent-provider provisioning/refresh, Tile/complication hosts and disconnected-watch lifecycle with actual devices and accounts.
- A local search/dictation extension can improve record lookup and reviewed Planner creation independently of the assistant. Full system-level Siri parity remains subject to the documented Gemini/AppFunctions access and language limitations above, not merely pending shortcut code.
- Complete native support acceptance with the optional Android service configuration; the module and app entry point are implemented, with browser help available as fallback.
- Finish release-level visual/accessibility acceptance on small/large phones, tablets/foldables, light/dark, all four language modes and large fonts. A few emulator screenshots do not establish polish on every supported form factor.

Do not add a Planner cloud-sync service, bidirectional Calendar import, purchased Compute wallet or extra AI provider merely to fill a supposed gap: the referenced iOS implementation does not ship those capabilities. Its broader grade distribution/period analysis is also explicitly deferred.
